01Read this first

I read your actual frontend repo before writing any of this (not just the backend PDFs), because the prompts below only work if they match your real files. Four things are different from the backend guide's assumptions:

Finding — no list endpoints yet

The backend Sprint 6 guide only built POST /quotations, GET /quotations/:id, and PATCH /quotations/:id/approve. There is no GET /quotations (list) or GET /projects (list) endpoint documented anywhere. Both issues below are scoped around that reality instead of pretending a list endpoint exists.

Finding — one established UI pattern to copy

src/components/dashboard/finance/FinanceDashboardClient.tsx + financeUtils.ts is the only fully-built dashboard feature in the repo (Quotations, Projects, Leads are still DashboardPlaceholderPage stubs). It already solves: a 5-state loading machine (loading / ready / empty / unavailable / error), a preview-data fallback when the API is down, form validation, and calling apiClient from @/lib/axios. Both prompts below tell Claude Code to mirror this file exactly rather than inventing a new pattern.

Finding — no frontend RBAC pattern exists yet

src/types/auth.ts types User.role as "ADMIN" | "MANAGER" | "CLIENT" — coarser than the backend's seeded roles (SALES_MANAGER, PROJECT_MANAGER, ACCOUNTANT, CLIENT_PORTAL_USER). No existing dashboard page hides actions by role today. Confirm with your backend teammate what role string the JWT actually puts in /auth/me before wiring any client-side show/hide logic — otherwise a button that should show for Sales Manager may never appear.

Finding — tests are source-inspection, not rendered

npm run test runs Node's built-in test runner (node --test) against test/*.test.mjs. There is no jsdom or React Testing Library installed. Existing tests (e.g. test/finance-dashboard.test.mjs) read the raw .tsx/.ts source with readFileSync and assert with regex — they check that certain strings, endpoints, and copy exist in the file, not that the component renders correctly in a browser. Every prompt below tells Claude Code to follow that exact convention.

As a Sales Manager, I want to generate a priced quotation from a lead

## Acceptance Criteria

### AC1: Happy path
Given a lead id and one or more line items (name, quantity, unit price)
When the Sales Manager submits the quotation form
Then POST /quotations fires with the raw items (no client-computed total)
  and the response quotation renders with its server-computed totalAmount
  and a PENDING_APPROVAL status badge
  and a success banner confirms the quotation was created

### AC2: Client-side validation
Given the items list is empty or a required field is missing
When the Sales Manager tries to submit
Then the form shows inline field errors and does NOT call the API
  (mirror validateFinancePaymentForm's approach in financeUtils.ts)

### AC3: Server validation surfaces cleanly
Given the backend still returns 400 VALIDATION_ERROR for some case the
  client didn't catch
When the response arrives
Then the form shows a dismissible error banner with the backend message,
  the form values are NOT cleared, and nothing crashes

### AC4: Lead not found
Given a leadId that the backend returns 404 LEAD_NOT_FOUND for
When the Sales Manager submits
Then a friendly "Lead not found" banner is shown and the form stays filled in

### AC5: Loading / empty / unavailable states
Given the quotation-service is unreachable
When the page loads
Then it shows a preview/mock fallback panel with a clear "not live" message,
  exactly like FinanceDashboardClient's "unavailable" state — the page
  must still be demoable if the backend is down

### AC6: PDF link (best-effort)
Given a returned quotation has a non-null pdfUrl
When it renders
Then a "View PDF" button opens it in a new tab; if pdfUrl is null, show
  "Preparing PDF..." instead (no polling required this issue)

- New files: src/types/quotation.ts, src/components/dashboard/quotations/
  QuotationsDashboardClient.tsx, src/components/dashboard/quotations/
