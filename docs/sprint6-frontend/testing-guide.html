01The testing convention this repo actually uses

Important — don't ask Claude Code for Jest or React Testing Library

This is the one place this frontend guide most needs to diverge from the backend Testing Guide PDF. The backend uses Jest with real database integration tests. This frontend has no Jest, no jsdom, and no @testing-library/react installed — package.json's test script is just node --test. Every existing test (test/finance-dashboard.test.mjs, test/analytics-dashboard.test.mjs, test/dashboard-layout.test.mjs) reads a component's raw source with readFileSync and asserts with regex — confirming specific strings, endpoint paths, and UI copy exist, not that the component actually renders correctly in a browser. Treat these as "contract" tests, not real rendering tests, and follow that exact pattern below. If a prompt asks for Jest/RTL, it will fail to install and break CI.

This also means these tests cannot catch runtime bugs (a broken useEffect, a bad prop type at render time). That's a real limitation worth calling out, not papering over — the manual verification steps in both PRs and the demo script in the Build Guide are what actually prove the feature works, on top of these tests confirming the code contains what it's supposed to.

04Claude Code master prompt

Prompt — write the tests 
You are writing source-inspection tests for the quotation UI in the
ConstructPro ERP frontend. This repo's test script is node --test - there
is no Jest, no jsdom, no React Testing Library, and you must not add any
of them. Every existing test in test/*.test.mjs (read
test/finance-dashboard.test.mjs first) works by reading a component's raw
source with readFileSync and asserting with regex via node:assert/strict.
Follow that exact pattern.

FIRST - read these files before writing anything:
 - test/finance-dashboard.test.mjs           (the pattern to copy)
 - src/app/dashboard/quotations/page.tsx
 - src/components/dashboard/quotations/QuotationsDashboardClient.tsx
 - src/components/dashboard/quotations/quotationUtils.ts
 - src/types/quotation.ts

TASK - create test/quotation-dashboard.test.mjs with these test() blocks:

1. "quotations page renders the dedicated quotation dashboard client"
   - assert.match on page.tsx source for /QuotationsDashboardClient/
   - assert.doesNotMatch for /DashboardPlaceholderPage/

2. "quotation dashboard client covers the required UI states"
   - assert.match on QuotationsDashboardClient.tsx / quotationUtils.ts
     for the actual empty-state, unavailable-state, and validation-error
     copy you find in those files (use the real strings, don't guess)

3. "quotation dashboard client calls the correct quotation-service endpoints"
   - assert.match for apiClient.post("/quotations", ...
   - assert.match for a template literal hitting `/quotations/${...}`
   - assert.match for a template literal hitting
     `/quotations/${...}/approve` via apiClient.patch

4. "quotation dashboard client handles the approval edge cases from BR-10.2"
   - assert.match for copy/branches covering: CONVERTED + projectId
     shown, REJECTED disabled state, an already-converted informational
     (non-error) path, and a retryable error state for downstream
     failures - use the real strings from the component, do not invent
     copy that isn't actually there

5. "quotation utils expose the expected helpers"
   - assert.match on quotationUtils.ts for the real exported function
     names you found (validateQuotationForm, normalizeQuotations,
     isQuotationUnavailableError, canCreateQuotation,
     canApproveQuotation, etc.) - list only the ones that actually exist

IMPORTANT RULES:
 - Read the actual files first - assert against real strings, not
   assumed ones. If a piece of copy or a helper name doesn't match what
   Issue #1/#2 actually produced, use what's really there.
 - Do not install or import jest, @testing-library/react, or jsdom.
 - Produce a complete, runnable file with all imports at the top - no
   placeholders or TODOs.
 - Run npm run test after writing the file and fix anything red before
   showing me the result.

is no jsdom/RTL in this repo. They catch regressions in wiring, copy,
and endpoint calls, but not runtime rendering bugs. Manual verification
steps in the Build Guide's PRs are still required before merging either
feature PR.
